# 量化前端工作台设计

日期：2026-06-17

## 背景

当前项目是 A 股量化数据采集层，已包含股票列表、交易日历、日 K 线、清洗、DuckDB 落库、质量报告、流水线日志和研究股票池视图。前端的第一阶段目标不是做完整交易系统，而是让使用者快速判断数据是否可用，并进入研究股票池检查样本。

## Visual Thesis

克制的暗色量化工作台：像 Linear 的秩序感叠加 Bloomberg-lite 的信息密度，只使用一枚绿色状态色，依靠字号、分割线、留白和右侧检查器建立高级感。

## Content Plan

### 1. 运行概览

首屏直接展示今天是否适合研究：

- 最新质量报告日期与生成时间。
- `quality_score`、`status`、`stock_count`、`date_range`。
- 最高优先级异常，例如当前报告中的“有数据股票仅 5 只”。
- 三个主动作：运行增量采集、查看质量报告、进入研究股票池。

### 2. 数据质量

用于解释数据是否可信：

- 缺失率、停牌数量、OHLC 异常、极端涨跌、source audit 对账状态。
- 已知天然缺失字段需要弱化展示，例如无 Tushare Token 时的 `adj_factor`。
- 每个异常给出处理建议，而不是只展示原始 JSON。

### 3. 研究股票池

围绕 `research_daily_universe` 做核心研究入口：

- 按交易日查询股票池。
- 支持筛选 `is_in_universe`、`exclude_reason`、交易所、行业、异常标记。
- 表格默认展示代码、名称、收盘价、涨跌幅、成交量、是否进入样本、剔除原因。
- 点击股票进入详情页。

### 4. 股票详情

用于检查单只股票是否适合研究：

- 展示日 K 线、成交量、涨跌幅。
- 显示未复权价格与可用的前复权价格。
- 展示 `flag_extreme`、`flag_suspended`、`flag_aligned`、`flag_invalid_ohlc`。
- 可选展示每日基本面和财务指标，但需要明确数据是否由 Tushare 提供。

### 5. 系统配置

第一阶段只读展示 `config.yaml` 的关键配置：

- 数据源、Tushare Token 是否配置、交易所范围。
- ST 过滤、新股过滤、并发、质量阈值。
- 数据库路径、日志路径、报告路径。

### 6. 日志与任务

展示流水线可观测性：

- `pipeline_log` 最近运行记录。
- `logs/pipeline.log` 摘要。
- `data/backups` 最近备份。
- 操作入口包括增量采集和全量重建；第一阶段可先做命令展示，后续再做真正执行。

## Interaction Thesis

- 首屏数字轻微入场，优先强调状态变化，不做装饰性动效。
- 点击异常后，右侧 inspector 展开原因、影响范围和建议动作。
- 股票池表格点击行后进入股票详情，使用平滑过渡保持研究工作流连续。

## 信息架构

```text
QuantOS
├── 运行概览
├── 数据质量
├── 研究股票池
│   └── 股票详情
├── 数据源审计
├── 系统配置
└── 日志与任务
```

## 数据来源映射

| 页面 | 主要数据来源 |
| --- | --- |
| 运行概览 | `data/quality_reports/*.json`、`pipeline_log` |
| 数据质量 | `QualityMonitor` 输出、`daily_kline` 标记字段、`data_source_audit` |
| 研究股票池 | `research_daily_universe` |
| 股票详情 | `daily_kline`、`daily_basic`、`financial_indicators`、`stock_list` |
| 系统配置 | `config.yaml` |
| 日志与任务 | `pipeline_log`、`logs/pipeline.log`、`data/backups` |

## 页面布局原则

- 使用三栏应用结构：左侧导航、主工作区、右侧 inspector。
- 首屏不放营销 hero，不使用泛 SaaS 卡片墙。
- 重要数字用大字号和分割线呈现；普通区域用列表、表格和矩阵。
- 只使用一个强调色表示“可用/活动/主动作”，警告和错误使用低饱和辅助色。
- 移动端优先隐藏侧栏和 inspector，保留主工作区的关键状态与表格。

## 阶段划分

### Phase 1：可运行原型

- 构建暗色量化工作台框架。
- 读取质量报告 JSON。
- 展示运行概览、异常 inspector、研究股票池列表。
- 支持股票详情基础查看。

### Phase 2：操作能力

- 接入流水线任务触发。
- 查看实时日志。
- 支持全量重建、增量采集、数据导出。

### Phase 3：策略运营

- 接入策略信号、回测结果、交易日志、风控提醒。
- 构建策略维度的表现分析页面。

## 非目标

- 第一阶段不做完整交易执行。
- 第一阶段不编辑 `config.yaml`。
- 第一阶段不承诺实时行情。
- 第一阶段不把质量分当成唯一判断，需要同时展示覆盖率和异常原因。

## 验收标准

- 打开首页后，5 秒内能判断今天数据是否适合研究。
- 当前“有数据股票仅 5 只”的问题必须在首页明确暴露。
- 用户能从首页进入研究股票池，并看见进入样本与剔除原因。
- 用户能打开单只股票详情，看到行情和质量标记。
- 界面保持克制、高级、信息密度适中，避免堆叠卡片和多色装饰。
